# ESP32 探地雷达射频部分现成模组分析

更新时间：2026-03-30

## 结论

有现成模组可以用，但没有一块“买来直接接 ESP32 就能做探地雷达”的低成本通用成品模组。

更现实的做法是把射频部分拆成几块现成板卡来搭原型：

1. `扫频源/本振模块`
2. `接收检测模块`
3. `LNA/功分/耦合器/开关等射频前端`
4. `宽带天线`

对 `ESP32` 来说，最容易落地的是 `SFCW` 或低复杂度 `FMCW` 原型，其中 ESP32 负责：

- SPI/I2C 控制射频芯片或模块
- 读取低速检测结果
- 做平均、背景扣除、IFFT/成像
- 存储和上传数据

如果希望“射频部分尽量少自己做”，当前最现实的两条路是：

1. `ADF4351/ADF4158 + AD8302 + LNA + 双天线`，做低成本扫频原型
2. `PlutoSDR / LimeSDR Mini 2.0`，先做算法验证和台架实验，再决定是否下放到 ESP32

## 针对 1 到 2 米浅层原型的推荐

如果目标明确是：

- 只做 `1 到 2 米` 浅层探测
- 接受“能看到较大埋设物/层间变化”的原型效果
- 希望 `尽量用现成模组`

那么推荐顺序应当收敛为：

### 第一选择：`ADF4351 + AD8302` 模组路线

建议扫频范围先放在：

- `300 MHz 到 900 MHz`
- 或 `200 MHz 到 800 MHz`

原因：

- 对 `1 到 2 米` 的浅层目标，这个频段比高 GHz 方案更现实
- 比 `6.5 GHz/8 GHz UWB` 或 `60 GHz 毫米波` 更有穿透能力
- `ADF4351` 官方覆盖 `35 MHz 到 4.4 GHz`
- `AD8302` 官方覆盖 `LF 到 2.7 GHz`
- 都能被 ESP32 以较低复杂度控制或读取

这个方案下，ESP32 只需要做：

- SPI 配置 `ADF4351`
- ADC 读取 `AD8302` 的幅度/相位输出
- 做平均、背景扣除、IFFT

这是当前最接近“模块化采购 + ESP32 可独立主控”的路线。

### 第二选择：`PlutoSDR` 直接做原型验证

如果你的优先级是“先尽快看到回波和成像趋势”，而不是“整机一定先由 ESP32 独立跑起来”，那么 `PlutoSDR` 更快。

但它更适合：

- 台架实验
- 上位机算法验证
- 天线和扫查方法调试

不太适合作为最终的 ESP32 射频子模块。

### 不建议作为这类原型的第一选择

- `DWM3000` 一类 UWB 定位模组
- `IWR6843AOP`、`BGT60TR13C` 一类 60 GHz/64 GHz 毫米波模组
- `ADF4158` 官方评估板

其中 `ADF4158` 芯片本身可用于 FMCW，但官方 `EVAL-ADF4158` 自带的是 `5.8 GHz VCO`，对 1 到 2 米浅层 GPR 原型并不是最合适的起步板。

## 为什么没有现成的便宜 GPR 一体模组

探地雷达和常见“测距雷达模组”不是一回事。

- 探地雷达通常更关注 `较低中心频率`、`较大带宽`、`稳定相位`、`强背景扣除`
- 地下介质损耗大，频率太高时穿透能力会明显变差
- 常见 UWB 定位模组、60GHz/77GHz 毫米波模组，主要面向 `空中测距、人体感知、定位`，不是土壤穿透

所以市面上大量“雷达模块”看起来现成，但并不适合做 GPR。

## 可用方案

### 方案 A：ADF4351 扫频源 + AD8302 幅相检测

这是最适合 `ESP32` 的入门原型路线。

组成建议：

- `ADF4351` 模块：作为扫频源/本振
- `AD8302` 模块或自制小板：做幅度和相位检测
- `LNA`：提高接收灵敏度
- `定向耦合器/功分器`
- `发射天线 + 接收天线`
- `外部高精度 ADC`

优点：

- 结构简单，ESP32 通过 SPI 就能控制
- 不需要高速 ADC
- 成本远低于 SDR 方案
- 适合做 `A-scan` 和低速 `B-scan` 原型

限制：

- `AD8302` 官方指标到 `2.7 GHz`
- 常见廉价 `ADF4351` 小板一致性一般，杂散、屏蔽、参考时钟质量参差不齐
- 仍然需要自己搭功分、参考链路、天线和机械扫描

结论：

如果目标是“先做出能看到埋设物/分层趋势的原型”，这是我最推荐的路线。

### 方案 B：ADF4158 FMCW/Chirp 路线

`ADF4158` 支持频率斜坡和波形生成，官方明确面向 `FMCW radar`。

优点：

- 比 ADF4351 更适合做连续 chirp
- 适合后续向更规范的 FMCW 架构演进

限制：

- 硬件和调试复杂度高于 ADF4351
- 依旧不是“一块板搞定”，仍需接收链路、天线、下变频/检测设计
- 对同步、线性度、泄漏抑制要求更高

结论：

如果你已经接受“不是最省事，但想做得更像正式雷达”，可以选它；如果只是先验证可行性，不如先上 ADF4351。

### 方案 C：PlutoSDR

`ADALM-PLUTO` 是现成 SDR 板，基于 `AD9363`，官方覆盖 `325 MHz 到 3.8 GHz`，`20 MHz` 瞬时带宽。

优点：

- 射频收发和采样链路已经集成
- 适合做台架实验、扫频实验、算法验证
- 文档和软件生态成熟

限制：

- 更像“带射频和采样的实验平台”，不是给 ESP32 直接独立驱动的小模组
- 实际上通常要配 `PC/Linux 主机`
- `325 MHz` 起步频率偏高，做深层穿透不占优
- `20 MHz` 瞬时带宽对高分辨成像有限

结论：

适合先验证“目标能不能被看见、处理链能不能跑通”；不适合直接作为“ESP32 自主整机”的最终射频模块。

### 方案 D：LimeSDR Mini 2.0

这是另一类成熟 SDR 板。当前官方销售页仍可见在售。

优点：

- 开放性强
- 适合快速做 RF 实验和算法验证
- 相比纯分立方案，少踩很多高速采样坑

限制：

- 成本明显高于 ADF4351 路线
- 仍然更依赖 PC/上位机，不是典型 ESP32 外设
- 对“做便携低成本探地雷达”帮助主要在验证阶段，不在最终产品形态

结论：

如果你更在意开发效率，而不是 BOM 成本，可以考虑它；否则不作为第一选择。

### 方案 E：ADL5960 一类 VNA 前端

`ADL5960` 是集成式 `VNA front end`，可以保留幅相信息，能力很强。

优点：

- 更接近矢量测量架构
- 适合做高质量反射测量、材料分析、S 参数风格实验

限制：

- 明显超出“ESP32 快速做一个 GPR 原型”的复杂度
- 配套链路、LO、ADC、校准、板级设计要求高
- 成本和集成难度都高

结论：

更像第二阶段或研究型方案，不是第一台原型机的优先选项。

## 不推荐直接用于 GPR 的现成模组

### UWB 定位模组，如 DWM3000

`DWM3000` 是 Qorvo 的 UWB 模块，工作在 `6.5 GHz` 和 `8 GHz` 通道，目标是高精度定位。

不推荐原因：

- 频率过高，不利于地下穿透
- 协议和用途偏向定位，不是开放式雷达测量前端
- 即使能做实验，也更接近“UWB 定位/短距穿透试验”，不是典型探地雷达

结论：

不要把它当作 GPR 射频模组采购。

### 60GHz/64GHz 毫米波模组，如 TI IWR6843AOP、Infineon BGT60TR13C

这些模组很成熟，但主要面向：

- 人体感知
- 手势识别
- 空中距离/速度检测
- 室内占位与存在检测

不推荐原因：

- 工作频率太高，土壤衰减非常严重
- 天线和波束特性针对近场/空中场景
- 不适合做地下层析或埋设物探测

结论：

它们是“现成雷达模组”，但不是“适合做探地雷达的现成模组”。

## 我建议的采购路线

### 最低风险路线

先买：

- `ESP32-S3` 开发板
- `ADF4351` 模块 2 块
- `AD8302` 模块 1 到 2 块
- `宽带 LNA`
- `功分器/耦合器`
- `双天线`
- `16-bit 外部 ADC`

原因：

- 最接近 ESP32 能独立控制的体系
- 采购成本可控
- 便于先做空气中和沙箱中的验证

### 最高开发效率路线

先买：

- `PlutoSDR` 或 `LimeSDR Mini 2.0`
- 宽带天线
- PC 上位机软件链路

原因：

- 更快看到原始 IQ 或频域数据
- 更快做算法验证和参数扫描
- 但之后如果要迁移到 ESP32，需要重构硬件架构

## 最终推荐

如果目标是：

### 1. 先做一台由 ESP32 主控的原型

选 `ADF4351 + AD8302` 路线。

这是“现成模组最多、与 ESP32 最匹配、难度最低”的方案。

### 2. 先验证探测与成像算法，不急着做低成本整机

选 `PlutoSDR` 或 `LimeSDR Mini 2.0`。

### 3. 想一步做到更像正式雷达

再考虑 `ADF4158`，不要一开始就上高复杂度 VNA 前端。
