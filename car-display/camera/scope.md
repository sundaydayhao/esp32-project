# 车辆盲区视觉显示系统 — 架构设计文档

## 1. 物理部署约束

| 位置 | 设备 | 说明 |
|------|------|------|
| 左后视镜外壳 | 摄像头节点 (左) | 监控左侧盲区，暴露在车外 |
| 右后视镜外壳 | 摄像头节点 (右) | 监控右侧盲区，暴露在车外 |
| 车内中控台 / A柱 | 显示主机 | 驾驶员可视区域，接转向灯信号 |

> **关键约束**：后视镜到车内中控台距离约 1.5~3m，DVP 摄像头信号线在此距离下信号完整性差，**不适合直接走线**。需要采用无线或压缩传输方案。

## 3. 节点详细设计

### 3.1 摄像头节点 (左/右，各一个)

**硬件**：

| 组件 | 型号 | 说明 |
|------|------|------|
| MCU | ESP32-S3-MINI-1 | 内置 WiFi，支持 DVP 摄像头 |
| 摄像头 | OV2640 | 160° 广角，DVP 接口 |
| 电源模块 | DC-DC 降压 12V→3.3V | 从车载电源取电 |
| 外壳 | 防水 IP54 | 安装在后视镜外壳内 |

**软件职责**：

```
摄像头节点软件流程:
┌─────────────────────────────────────┐
│  初始化                              │
│  1. 初始化 OV2640 (QVGA 320x240)    │
│  2. 初始化 ESP-NOW (配对显示主机)    │
│  3. 注册为 LEFT 或 RIGHT 节点        │
└──────────────┬──────────────────────┘
               │
               ▼
┌─────────────────────────────────────┐
│  主循环 (目标 15fps)                 │
│                                     │
│  1. esp_camera_fb_get()             │
│     采集 RGB565 帧 (320x240)        │
│                                     │
│  2. JPEG 压缩                       │
│     frame2jpg() → ~8~15KB          │
│                                     │
│  3. ESP-NOW 分包发送                 │
│     每包 ≤ 250 字节                  │
│     包头: [节点ID][帧序号][包序号]   │
│                                     │
│  4. 等待 ACK / 超时重传              │
└─────────────────────────────────────┘
```

**关键参数**：

| 参数 | 值 |
|------|-----|
| 摄像头分辨率 | 320×240 (QVGA) |
| 像素格式 | JPEG (直接输出，减少传输量) |
| JPEG 质量 | 15~20 (约 8~15KB/帧) |
| 目标帧率 | 10~15 fps |
| ESP-NOW 速率 | 1Mbps，单帧传输时间 ~80~120ms |

## 4. 通信协议设计 (ESP-NOW)

### 4.1 数据包格式

```
┌──────────────────────────────────────────────────────┐
│                  ESP-NOW 数据包 (≤250字节)            │
├────────┬────────┬────────┬────────┬──────────────────┤
│ 字节0  │ 字节1  │ 字节2  │ 字节3  │ 字节4~249        │
├────────┼────────┼────────┼────────┼──────────────────┤
│节点ID  │帧序号  │包序号  │总包数  │ JPEG 数据分片    │
│0=左    │0~255   │0~N-1   │N       │ (最多246字节)    │
│1=右    │        │        │        │                  │
└────────┴────────┴────────┴────────┴──────────────────┘
```

### 4.2 帧重组逻辑

```
接收端帧重组:
- 维护两个重组缓冲区: left_buf[16KB], right_buf[16KB]
- 按 [节点ID][帧序号][包序号] 重组
- 所有包收齐后触发 JPEG 解码
- 超时 (200ms) 丢弃不完整帧
```

### 4.3 MAC 地址配对

```
方案: 固定 MAC 地址 (烧录时写入 NVS)
- 摄像头节点启动时广播自身 MAC + 节点ID
- 显示主机收到后保存并建立 ESP-NOW peer
- 支持热插拔 (摄像头断电重连自动恢复)
```

## 5. 电源方案

```
车载电源 (12V)
    │
    ├──[DC-DC 12V→5V 2A]──→ 左后视镜节点 (ESP32-S3 + OV2640)
    │
    ├──[DC-DC 12V→5V 2A]──→ 右后视镜节点 (ESP32-S3 + OV2640)
    │
    └──[DC-DC 12V→5V 3A]──→ 显示主机 (ESP32-S3 + LCD)
                                │
                                └──[LDO 5V→3.3V]──→ ESP32-S3

转向灯信号 (12V 闪烁)
    │
    ├──[PC817 光耦]──→ 显示主机 GPIO39 (左转)
    └──[PC817 光耦]──→ 显示主机 GPIO40 (右转)
```

## 8. 关键技术选型对比

| 方案 | 传输方式 | 延迟 | 复杂度 | 成本 | 推荐 |
|------|---------|------|--------|------|------|
| **方案A (本方案)** | ESP-NOW | ~100ms | 中 | 低 | ✅ |
| 方案B | WiFi MJPEG | ~200ms | 高 | 低 | ❌ |
| 方案C | 有线 UART | ~50ms | 低 | 低 | ⚠️ 需走线 |
| 方案D | 有线 DVP 延长 | ~33ms | 低 | 低 | ❌ 信号衰减 |
| 方案E | 有线 MIPI CSI | ~16ms | 高 | 高 | ❌ 成本高 |

**选择 ESP-NOW 的理由**：
- 无需路由器，点对点直连
- 延迟约 80~120ms，满足盲区辅助显示需求（非自动驾驶）
- 穿透车身金属结构，信号稳定
- 两个摄像头节点独立工作，互不干扰
- 成本最低（仅需 ESP32-S3 模块）
